# Telegram Forum CRM Work-order System
# 🐰 话题工单增强版（三源融合）— Telegram 双向私聊工单机器人

基于 Cloudflare Workers + KV 的 Telegram 双向私聊机器人：访客私聊 → 人机验证 → 自动在大本营群建立独立话题工单 → 管理员在话题内回复即直达访客私聊。

本代码以「话题工单增强版」为骨架，融合了「流氓兔」与「火佬」两套源码的全部核心能力，并将 D1 数据库层全部适配为 KV 实现，保持单文件、零外部依赖、一键部署。

## ✨ 功能总览

### 工单核心
- 🔐 **暗号门禁 + Webhook 防伪造**：`SECRET_PATH` 路径门禁 + Telegram 官方 `secret_token` 校验，双重防伪造 Update
- 🧵 **话题工单**：每位访客自动获得独立话题房间，话题名实时反映备注/封禁状态
- 👎 **双向粉碎**：管理员对任意一侧消息贴 👎 反应，双向对称删除（消息映射 30 天有效）
- 🛡️ **智能中继回复**：文字直发 → copyMessage → 媒体 file_id 直发 → caption 降级，四级保障
- 🚑 **应急自愈**：`/binduser <ID>` 强制绑定房间 + 话题↔用户映射反向溯源自愈
- 📌 **置顶情报栏 + 情报卡片**：单行置顶栏（昵称/备注/曾用名/用户名/ID）+ 底部交互卡片，被删自动重建
- 📇 **案底流水**：访客曾用名自动追踪，全角对齐悬垂缩进排版
- 🧪 **模拟陌生人测试**：`/test on|off` 或面板按钮，超管自测全流程

### 安全与验证
- 🧮 **满级验证码**：加减混合运算、30 秒限时、超时/答错自动换题、累计错 3 次触发 5 分钟临时封禁
- 📨 **消息暂存无痕补发**：未验证访客的首条消息暂存，验证通过后自动补发，无感对接
- 🔒 **建房并发锁 / 验证并发锁**：并发消息不会重复建话题、不会重复弹验证
- 🚫 **反垃圾**：静态广告关键词过滤（警告 24h → 再犯永久封禁）+ 黑名单瞬时索引与分页管理

### 双向增强
- ✏️ **双向编辑同步**：访客编辑消息 → 话题收到新旧内容对比；管理员编辑回复 → 访客收到新旧内容对比（含时间戳）
- 🔕 **静音通知**：静音用户来信在群内静默投递
- 👤 **资料卡增强**：「查看用户资料」按钮（用户名 t.me 直链 / tg:// 深链 + 隐私受限自动降级）、「📌 置顶卡片」
- 📋 **用户资料卡汇总话题**：新用户接入时自动同步 #新用户连接 卡片（带跳转按钮）
- 💾 **消息备份群组**：所有访客消息带抬头备份到指定群组
- 🤖 **关键词自动回复**：正则规则命中即自动回复，可增删管理
- 🚫 **可配置屏蔽关键词**：正则关键词 + 计数阈值，达阈值自动永久封禁
- 🔗 **8 类内容过滤开关**：用户/群组/频道转发、音频语音、贴纸 GIF、媒体、链接、纯文本
- 📣 **群发系统**：`/broadcast`（文本 / 复制 / 媒体+说明四种模式）、`/broadcast_status` 报告、`/broadcast_retry_failed` 失败重试、429 限速自动等待、拉黑/注销用户自动标记
- 🧑‍💻 **协管员白名单**：授权协管员可参与话题回复，私聊自动绕过验证
- 🔐 **验证模式切换**：算术题（默认）⇄ 一键点击验证；欢迎语可配置

## 🚀 部署步骤

1. **创建 Worker**：Cloudflare 后台 → Workers → 创建，将 `_worker.js` 全文粘贴部署
2. **绑定 KV**：Worker [设置] → [绑定] → KV 命名空间，变量名填 `BOT_DB`（必须全大写）
3. **配置环境变量**（[设置] → [变量和机密]，代码内无任何密码）：

   | 变量名 | 必填 | 说明 |
   |---|---|---|
   | `BOT_TOKEN`（或 `TOKEN`） | ✅ | @BotFather 发的机器人 Token |
   | `OWNER_ID` | ✅ | 超管纯数字 ID（@userinfobot 查询） |
   | `SECRET_PATH`（或 `PASSWORD`） | 建议 | Webhook 暗号路径，默认 `/XXXXXXXXXX` |
   | `WEBHOOK_SECRET` | 建议 | Webhook 防伪造密钥（任意随机串） |
   | `OWNER_GROUP_IDS` | 可选 | 备用授权群组 ID，逗号分隔 |

4. **激活 Webhook**：浏览器访问 `https://你的Worker域名/setup`，返回 `"ok":true` 即成功
   > ⚠️ 每次更新代码后请重新执行本步（新版本订阅了 `edited_message` 以支持编辑同步）
5. **绑定大本营**：新建开启「话题(Topics)」功能的超级群 → 拉入机器人 → 授予 **100% 管理员权限**（必须包含：管理主题、删除消息、置顶消息）→ 群内发送 `/bind`
6. **验证**：机器人私聊发送 `/start` 呼出控制台

## ⚠️ 已知限制与注意事项

1. **群发规模受 Worker 子请求上限约束**：Cloudflare 免费版单请求约 50 个子请求、付费版 1000 个。每位群发用户消耗 1~2 个子请求，目标过多时群发会中途截断且报告不会保存。用户量大时建议分批（本限制为平台约束，原双向 bot 源码同样存在）
2. **编辑同步仅覆盖文本/说明文字**：纯媒体消息（无文字）编辑无法比对内容，会跳过通知
3. **管理员编辑回传要求原文已存档**：copyMessage 成功的媒体消息（无 caption）被编辑时无法比对，静默跳过
4. **解封后需重新验证**：封禁会清除验证态，解封后访客需重新完成人机验证（安全设计）
5. **转发来源过滤双策略**：用户/群组/频道转发三类开关全部为「屏蔽」时，转发消息走严格警告→封禁；任一开启后改为温和提示过滤
6. **服务器消息自动清理**：置顶/话题编辑产生的系统提示消息会被自动删除，请确保机器人有删除消息权限

## 部署流程

### 1. 创建 KV 数据库并绑定
1. 在 Cloudflare 控制台进入 **Storage & Databases** -> **KV**，创建一个命名空间（例如 `tg-crm-kv`）。
2. 打开已创建的 Worker -> **Settings** -> **Bindings**。
3. 添加 **KV Namespace Binding**，Variable Name 必须严格填写为 **`BOT_DB`**，选择刚才创建的命名空间。

### 2. 部署代码与配置环境变量
1. 将 `worker.js` 代码粘贴至 Worker 编辑器中并保存部署。
2. 在 **Variables and Secrets** 中添加 `BOT_TOKEN`、`OWNER_ID`、`WEBHOOK_SECRET` 等环境变量。

### 3. 一键配置 Telegram Webhook
部署完成后，使用浏览器访问：
```text
https://<你的Worker域名>/setup
```
若返回 `{"ok": true, "result": true, "description": "Webhook was set"}`，则说明 Webhook 已成功接入官方 Telegram 服务端。

### 4. 检查服务健康状态
浏览器访问：
```text
https://<你的Worker域名><SECRET_PATH>
# 示例：https://crm.yourname.workers.dev/123XXXX
```
页面将回显当前 Token、KV、Webhook 防伪造以及群组绑定的健康诊断状态。

## 群组设置与绑定

### 1. 超级群要求
* 必须使用 **开启了 Topics（话题）** 的超级群（Supergroup）。
* 将机器人拉入群组，并提升为管理员，赋予以下权限：
  * **Manage Topics（管理话题）**
  * **Pin Messages（置顶消息）**
  * **Delete Messages（删除消息）**

### 2. 绑定大本营
群主或超管在群内任意位置发送：
```text
/bind
```
机器人回复 `绑定成功` 后，当前超级群即被持久化保存为工单处理中心。

## 常见问题排查

* **建房被拒绝（`chat is not a forum` / `not enough rights`）**：
  * 检查群组是否开启了 Topics 功能，以及机器人是否拥有 `Manage Topics` 管理员权限。
* **回复提示“该房间未关联到访客 ID”**：
  * 该话题属于人工手动创建或 KV 索引丢失，直接在话题内发送 `/binduser <访客ID>` 即可立即恢复双向通讯。
* **多媒体消息发送受限**：
  * 若群内发送纯图片/多媒体提示无法复制，请前往群设置 -> **Group Type** -> 关闭 **Restrict saving content（限制保存内容）**。纯文本消息系统已内建原生直发通道，不受此项限制。
